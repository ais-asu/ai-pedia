# Roadmap

What to build next, in rough order. The site itself is stable (v1.0.0). The
biggest gap is content: there are two articles. Most items below either make
writing easier or make the site worth coming back to.

Each item says what "done" means. Tick items off in the same pull request that
finishes them. docs/ARCHITECTURE.md describes the current system.

## 1. Before promoting the site

These should land before any outreach, since first visitors will hit them.

- [ ] **Document the hosting.** Find where ai-pedia.ais-asu.com is deployed
  (no deploy status shows up on pull requests), who has access, and how a
  deploy is triggered. Done when README "Maintaining" names the host and at
  least two officers have access.
- [ ] **Stop hotlinking images.** `content/supervised/linear-regression.md`
  loads two images from geeksforgeeks.org and cloudera.com. Replace them with
  our own images in `public/images/`, drawn or generated by us. Done when no
  article references an external image host.
- [ ] **Fix or remove the search action.** The WebSite JSON-LD in
  `app/layout.tsx` advertises `/learn?search=...`, but nothing reads that
  parameter. Either open the command palette with the query when `?search=` is
  present, or drop `potentialAction`.
- [ ] **Content check in CI.** Add `scripts/check-content.ts`, run it in
  `ci.yml`, and fail on: invalid file or folder names, notebooks that do not
  parse, missing `title` or `description`, `VZ-` ids not in the registry,
  `/images/...` paths that don't exist, and `/learn/...` links to articles that
  don't exist. Today, all of these are skipped silently or only show up on the
  page.
- [ ] **Add CODEOWNERS and branch protection** on `main`: required CI, and one
  review. Add a second maintainer so the project doesn't depend on one person.

## 2. Content and contributors

The site is only as useful as what is on it. Target: 20 articles by the end
of the semester, at least three per category.

- [ ] **Topic list.** Open one issue per article we want, labeled
  `article-request`, grouped by category. A starting set:
  - supervised: logistic regression, decision trees, random forests, SVMs,
    k-nearest neighbors, gradient descent, regularization, the bias-variance
    tradeoff
  - unsupervised: k-means, hierarchical clustering, PCA, t-SNE and UMAP,
    Gaussian mixtures
  - reinforcement: Markov decision processes, multi-armed bandits,
    Q-learning, policy gradients
  - statistics: probability basics, hypothesis testing, Bayesian inference,
    maximum likelihood, cross-validation
  - new category, deep learning: perceptrons, backpropagation, CNNs, RNNs,
    attention and transformers, embeddings
- [ ] **Issue templates.** Add "Request an article", "Claim an article" and
  "Report an error". A claimed issue is assigned to its writer, so two people
  don't write the same article.
- [ ] **Article template.** Add `docs/article-template.md` with the frontmatter
  and a suggested outline: intuition, the math, a worked example, code, common
  pitfalls, further reading.
- [ ] **Content review checklist** for maintainers: the math is right, symbols
  are defined, the code runs, sources are cited, images are ours. Add it to
  the PR template for content changes.
- [ ] **Owners per category.** One officer or member owns each category,
  reviews its PRs, and keeps its topic issues moving.
- [ ] **Writing sprints.** One or two sessions a semester where members write
  or review articles together, with a small prize or shoutout.
- [ ] **Workshop to article.** Every AIS technical workshop produces an
  article or notebook in AI Pedia, so the material outlives the event.
- [ ] **Contributor credit.** Link `contributors` to GitHub profiles, and add
  a contributors page that lists everyone and their articles.

## 3. Jupyter notebooks

Current state: `.ipynb` files in `content/` are rendered as articles at build
time, with Markdown cells, highlighted code, and saved outputs (images, HTML
tables, text, tracebacks). No notebook article exists yet, so this path has
never been used on the live site. What is missing:

- [ ] **First notebook article.** Add one real notebook, for example gradient
  descent from scratch with plots, to prove the pipeline end to end.
- [ ] **Open in Colab and Download buttons** on notebook articles. Colab can
  open files straight from GitHub:
  `https://colab.research.google.com/github/theaisocietyasu/ai-pedia/blob/main/content/<category>/<slug>.ipynb`.
  This is the cheapest way to let readers run the code.
- [ ] **Notebook checks in CI** (as part of the content check): the file
  parses, it has saved outputs, and it's under a size limit (say 5 MB).
- [ ] **Move output images out of the page.** Write base64 images to
  `public/` at build time and reference them by URL, so large notebooks don't
  bloat the HTML.
- [ ] **Plotly outputs.** Render `application/vnd.plotly.v1+json` outputs with
  plotly.js on the client. That covers most interactive charts in teaching
  notebooks, without running any notebook code.
- [ ] **Code blocks in Markdown articles.** Add an "Open in Colab" option for
  a fenced Python block, generating a one-cell notebook. Optional.
- [ ] **Run in the browser (later).** Run Python cells in the page with Pyodide
  or JupyterLite, so readers can change a value and rerun. This is heavy (the
  Pyodide runtime is tens of MB, loaded on demand), so only do it once there
  are enough notebooks to justify it.

## 4. Reading and learning features

- [ ] **Prerequisites.** Add optional `prerequisites: [category/slug]` and
  `next: [...]` frontmatter. Show a "Before you read" box and a "Read next"
  list on the article. Draw these as real edges on the map, so it shows
  learning paths and not just proximity.
- [ ] **Full-text search.** Build a search index of article bodies at build
  time (for example with MiniSearch or Pagefind) and load it on the first
  Cmd/Ctrl+K. Right now only titles and descriptions are searched.
- [ ] **Related articles** at the end of each article: same category first,
  then shared prerequisites.
- [ ] **Glossary.** A `content/_glossary.md` with term definitions, shown as
  hover cards when a term is marked in an article, plus a glossary page.
- [ ] **Self-check questions.** A few multiple-choice questions at the end of
  an article, written in the article file and checked in the browser. No
  accounts.
- [ ] **Learning paths.** A few curated sequences ("ML in 10 articles",
  "Statistics for ML") on their own pages.
- [ ] **Dark mode for articles.** The tokens exist (`data-theme="space"`).
  Add a light and dark reading theme that follows the system setting.
- [ ] **Print stylesheet**, so an article prints or saves to PDF cleanly.
- [ ] **Per-article Open Graph images.** Generate one per article with the
  title and category, so links shared in Discord and LinkedIn look distinct.

## 5. Visualizations

- [ ] **Visualization gallery.** A page (dev-only, or public at
  `/visualizations`) that renders every registered `VZ-` component, so writers
  can see what exists and developers can test in isolation.
- [ ] **Shared chart kit.** Pull the common pieces of the linear regression
  set (axes, sliders, parameter panels, the color tokens) into
  `components/visualizations/shared/`, so a new visualization is mostly its
  own logic.
- [ ] **Visualizations for new articles.** Pair each new core article with
  one: decision boundary for logistic regression, centroid updates for
  k-means, projection for PCA, a gridworld for Q-learning, attention weights
  for transformers.
- [ ] **Visualization contribution guide.** A short section in
  CONTRIBUTING.md on building one with the shared kit, with a worked example.

## 6. Engineering quality

- [ ] **Tests.** Vitest for `lib/content.ts`, `lib/notebook.ts`,
  `lib/embeds.ts` and the Markdown sanitizer (a fixture article with script
  and event-handler payloads must come out clean). Playwright smoke test for
  the home page, one category page and one article page. Run both in CI.
- [ ] **Content-Security-Policy header** in `next.config.ts`. KaTeX and the
  highlighter need `style-src 'unsafe-inline'`. Frames are limited to the
  embed allowlist.
- [ ] **Accessibility.** Keyboard navigation on the map (Tab through
  categories and articles, Enter to open), a visually hidden list of the map's
  nodes for screen readers, and an axe check in the Playwright run.
- [ ] **Performance budget.** Track the JavaScript on the home and article
  pages in CI. Make sure three.js only loads on pages that use it.
- [ ] **Dependency upgrades.** Next.js 16, lucide-react 1.x, katex 0.18.
  Upgrade one at a time and check the map and an article by hand.
- [ ] **Analytics.** Privacy-friendly page views (PostHog, which Bedrock
  already uses, or Plausible), to learn which articles are read and where
  readers drop off. No cookies banner needed if it's cookieless.
- [ ] **Error monitoring** for client-side errors on the map and
  visualizations.

## 7. Growth

- [ ] **Launch.** Announce in AIS Discord, SoDA, and ASU CS channels once
  section 1 is done and there are at least 8 articles.
- [ ] **Link from the AIS website** navigation and workshop pages.
- [ ] **Search Console.** Verify the domain (the env vars already exist), and
  submit the sitemap.
- [ ] **Course partnerships.** Ask ASU instructors and TAs for intro ML and
  statistics courses to link relevant articles as supplementary reading.
- [ ] **Article of the week** post on AIS socials, with a clip of its
  visualization.
- [ ] **Open to other clubs.** Invite SoDA and other ASU clubs to own
  categories (data engineering, AI ethics, robotics). Articles from other
  schools' AI clubs are welcome through the same PR process.

## 8. Bedrock (future)

Bedrock is the shared infrastructure for student organizations. AI Pedia
should stay a static site that builds from this repo. Bedrock would read from
it rather than host it:

- [ ] Expose AI Pedia articles as a read-only resource in Bedrock's MCP
  server and API (title, description, URL, Markdown source), built from this
  repo or the `/api/article/...` JSON.
- [ ] Show contribution stats (articles, contributors, recent merges) on the
  Bedrock officer dashboard.
- [ ] Link Bedrock events (workshops) to the articles they produced.
- [ ] Revisit hosting under Bedrock's deploy setup once it exists.

## Not planned

- A database, CMS or login. Pull requests are the editing workflow.
- Comments or forums on articles. Discussion stays in Discord or GitHub
  issues.
- AI-generated articles published without human review.
